## القرارات المؤكدة من المستخدم

«نعم، ٢٥٠ لكل المبيعات الجديدة، والمبيعات السابقة تفضل زي ما هي».

هذا يحسم استخدام آخر سعر شراء مؤكّد لكل المبيعات الجديدة بما فيها استهلاك المخزون القديم. لا متوسط تكلفة، ولا إعادة حساب للمبيعات السابقة.

وقرارات P03 المؤكدة: آخر تكلفة واحدة لكل صنف عبر مستودعات التاجر؛ الأحدث حسب ترتيب تأكيد الاستلام في النظام؛ يمنع تأكيد فاتورة إذا اختلفت التكلفة الفعلية للوحدة الأساسية للصنف بين حالتي المخزون. الخصم والشحن الموزعان يدخلان في التكلفة النهائية.

قرارات المراحل اللاحقة المؤكدة: الإيراد عند تأكيد بيع POS أو قبول الطلب الإلكتروني، والتكلفة عند الاستهلاك الفعلي؛ يمنع البيع إذا غابت تكلفة أي مكون مطلوب؛ سداد المورد مرتبط بسحب نقدي/خزنة موجودة؛ الضريبة مؤجلة.

تأكيدات المستخدم الأخيرة: يوزع خصم الطلب حسب قيمة كل بند قبل الخصم، وتُضاف المبيعات التاريخية المؤكدة بإيرادها المحفوظ مع بقاء التكلفة مجهولة وعدم تعديل الأسعار السابقة.

## خط الأساس قبل P01

- قبل بدء P01 كانت التوسعة توثيقًا فقط. تحديث هذه المهمة يضيف تكلفة الفاتورة في API وdatabase والعقود والواجهة.
- المشتريات القائمة تحفظ المورد والمستودع والكميات، وتؤكد الاستلام؛ لا أسعار مالية في عقد بند الشراء الحالي.
- وصفات ومتطلبات استهلاك محفوظة وحركات استهلاك/استعادة موجودة في source؛ لا يعتبر وجودها تسليمًا لتكلفة البيع.
- لم تُشغّل اختبارات أو فحوص آلية، ولم تُنفذ معاملات مالية أو migrations. المراجعة الحالية قراءة source وروابط الوثائق.
- مساحة العمل بها تغييرات مستقلة سابقة، بما فيها API وواجهات ووثائق؛ ليست جزءًا من هذه الميزة ولا يجوز نسبتها إلى مراحلها.
- إصلاحات السايدبار وزر إنشاء صنف المخزون السابقة ليست تسليمًا لأي مرحلة من مراحل التسعير والربحية.

## حالة P12 الحالية والخطوة التالية

طُبقت migration `20261114213000_backfill_order_revenue` على قاعدة التطوير المحلية بنجاح (79 migrations). قبلها كان هناك 16 سطرًا بلا snapshots؛ بعد التطبيق، التجميع يطابق 8 أسطر POS مكتملة بإيراد 1,479.00 جنيه، وسطرين POS pending بإيراد 3.00 جنيه، وسطر storefront accepted بإيراد 510.00 جنيه، وسطرين storefront ready بإيراد 615.00 جنيه. أسطر POS pending داخلة لأن مسار POS الحالي يثبت الإيراد وقت إنشاء البيع؛ الطلبات storefront pending الثلاثة بقيت بلا إيراد. كل الـ16 ما زالت بلا تكلفة محفوظة، وعدد cost snapshots ظل صفرًا. لم تُنشأ دفعات أو حركات نقدية. لا يوجد طلب كوبون قديم في قاعدة التطوير، لذلك لم تتوفر عينة بيانات للمقارنة اليدوية لتوزيعه.

توجد 4 استردادات قديمة غير منسوبة لسطور بقيمة 6.61 جنيه؛ تظل ظاهرة منفصلة. بعد طلب المستخدم اختبارًا آليًا، شُغلت الاختبارات الوحدوية الموجهة: 17 ناجحة، 0 فاشلة. لم أستخدم Chrome وفق توجيه المستخدم. يلزم فحص يدوي لخصم كوبون متعدد السطور ومقارنة سجلّات التكلفة المعروفة قبل إغلاق P12. عند نقص التكلفة، التكلفة والربح والهامش تظهر غير مكتملة بدل عرض قيمة صفرية مضللة.
