# فواتير الشراء والتكلفة وربحية المنتجات

تاريخ الإنشاء: 2026-11-14. الحالة: **مخرجات P01–P11 موجودة؛ القبول اليدوي في P12 ما زال مطلوبًا**.

الهدف: تسجيل قيمة المشتريات، ثم ربط تكلفة الخامات والمنتجات بالمبيعات، وصولًا لتقارير ربحية المنتج والمنيو والفرع.

## القرار الأساسي المؤكد

نعتمد **آخر سعر شراء مؤكّد** لحساب تكلفة المبيعات الجديدة، وليس متوسط تكلفة المشتريات.
لو آخر سعر تغيّر من ٢٠٠ إلى ٢٥٠ جنيه، نستخدم ٢٥٠ لكل بيعة جديدة حتى لو كانت الكمية من مخزون قديم.
المبيعات السابقة تحتفظ بالتكلفة المسجلة وقتها. ينطبق نفس المبدأ عند انخفاض السعر.

التقرير يسمي هذا بوضوح «مجمل الربح على أساس آخر سعر شراء». قيمة فاتورة الشراء التاريخية لا تتغير، وهذه السياسة لا تعني إعادة تقييم محاسبية تلقائية للمخزون القديم.

## طريقة العمل

1. اقرأ المواصفة والمرحلة التالية وحالة العمل قبل أي تعديل.
2. نفّذ شريحة واحدة قابلة للاستخدام، تشمل الحفظ والواجهة عندما تتطلب المرحلة ذلك.
3. احسم القرارات المفتوحة التي تخص الشريحة قبل تنفيذها؛ المقترحات ليست موافقات مستخدم.
4. راجع سيناريوهات القبول يدويًا، وسجّل النتيجة والأدلة والقيود في progress.
5. أغلق المرحلة فقط بعد اكتمال شروطها، ثم انتقل للمرحلة التالية ضمن نطاق التكليف.

بدأ التنفيذ بعد تكليف المستخدم «go» وحُسمت قرارات التسعير، مواعيد الإيراد والتكلفة، منع البيع مع تكلفة مفقودة، وربط دفعة المورد بحركة نقدية موجودة. مخرجات الشراء والتكلفة والحركات والمبيعات والمرتجعات والسداد والتقارير موجودة في المصدر.

قاعدة التطوير على localhost:5433 متاحة؛ Prisma يرى 78 migration ولا توجد migrations معلّقة، واستعلام مباشر أكد وجود عمود `purchase_invoices.subtotalAmount` الذي ظهر مفقودًا في سجل سابق. فحص القراءة فقط وجد فاتورتين مؤكّدتين وفاتورتين مسودتين و16 سطر طلب و4 استردادات، دون دفعات مورد أو إشعارات رصيد أو تصحيحات مسجلة. حسب توجيه المستخدم لم أستخدم Chrome أو أضف بيانات اختبارية مالية؛ لذلك لا تزال مراجعة النتائج والتدفقات التي تكتب بيانات معلقة. لم تُشغّل اختبارات أو lint أو build أو typecheck وفق تفضيل المشروع.
